# Project Structure

## Purpose

This document defines the intended workspace layout for Yui VRM AI Studio. The goal is to keep source, generated artifacts, public distribution copies, and temporary platform work separated.

## Source Of Truth

`unity/` is the canonical Unity project unless a dated status document explicitly says a temporary Unity copy is being merged back.

The former iOS patch workspace at `builds/unity_2022_3_62_patch_test/unity` has been merged back into canonical `unity/` as of 2026-06-17. Treat it as legacy reference material only until it is archived or deleted; do not make new source edits there.

## Top-Level Layout

| Path | Role | Tracked? | Notes |
| --- | --- | --- | --- |
| `unity/` | Canonical Unity source project | Yes, except generated Unity dirs | App code, scenes, packages, project settings. |
| `backend/` | Backend source | Yes, except local env/cache/data | FastAPI app, provider integrations, tests. |
| `scripts/` | Build, audit, and service automation | Yes | Scripts must be profile/platform explicit. |
| `docs/` | Durable project documentation | Yes | Status docs, rules, release notes, handoffs. |
| `tools/` | Helper tool source | Yes | Example: file picker helper. |
| `installer/` | Installer source/config | Yes | Installer definitions, not generated installers unless intentional. |
| `deploy/` | Deployment descriptors | Yes | Docker and deployment support. |
| `icon/` | App icon source assets | Yes | Keep generated variants only if reproducible need exists. |
| `runtime/` | Local runtime state | No | PIDs, service state, local temp. |
| `logs/` | Local logs | No | Summarize important findings in docs instead. |
| `downloads/` | External downloaded packages | No | Cache only. |
| `backend/data/audio/` | Generated TTS WAV cache | No | Bounded by backend retention settings. |
| `benchmarks/` | Local benchmark outputs | No | Generated by scripts such as `scripts/bench_tts.py`; summarize results in docs instead. |
| `builds/` | Legacy generated build outputs | No | Do not add new source workspaces here. |
| `artifacts/` | Generated release/build artifacts | No | Preferred future output root for builds and packaged exports. |
| `public/` | Generated or nested public repo copy | No in root repo | Public repo has its own lifecycle. Keep it clean before release. |

## New Artifact Layout

New generated outputs should move toward this structure instead of adding more ad hoc directories under `builds/`:

```text
artifacts/
  personal/
    ios/
      0.1.0-alpha.1/
        debug/
          xcode/
          app/
    macos/
    windows-x64/
    android-arm64/
  public/
    windows-x64/
      0.1.0-alpha.1/
        release/
```

`builds/` remains a legacy location until existing scripts are migrated. New scripts should write to `artifacts/` or have an explicit compatibility reason.

## Temporary Workspaces

Temporary Unity or platform workspaces should not live inside `builds/`. Use one of these patterns:

- `worktrees/<purpose>/` for deliberate source workspaces.
- `/private/tmp/...` for disposable generated exports.
- `artifacts/.../xcode` for generated Xcode projects.

Every temporary workspace must have an owner status doc and an exit plan: merge, archive, or delete after verification.

## Unity Platform Source Layout

Keep platform-specific Unity code behind a shared facade whenever practical.

| Path | Role |
| --- | --- |
| `unity/Assets/App/Scripts/Platform/` | Shared platform facades and small cross-platform adapters. Feature/UI code should call these APIs instead of native plugins directly. |
| `unity/Assets/App/Scripts/Platform/iOS/` | iOS-only managed shims, guarded with `UNITY_IOS && !UNITY_EDITOR`. |
| `unity/Assets/Plugins/iOS/` | iOS native plugin source and plugin metadata. |
| Future `unity/Assets/App/Scripts/Platform/Android/` | Android-only managed shims, created only when needed. |
| Future `unity/Assets/Plugins/Android/` | Android native/JAR/AAR plugin assets, created only when needed. |
| Future `unity/Assets/App/Scripts/Platform/Windows/` and `Platform/macOS/` | OS-specific managed adapters when behavior genuinely diverges. |

Do not split whole features by OS unless the implementation is truly platform-exclusive. Shared realtime conversation logic, backend clients, avatar selection, and build-profile defaults should remain in common app code.

## Public Repository Hygiene

The generated public repo/package must not contain:

- Unity generated directories: `Library`, `Logs`, `Temp`, `UserSettings`, `obj`
- Python caches: `__pycache__`, `.pytest_cache`, `*.pyc`
- macOS metadata: `.DS_Store`
- private assets, private avatar defaults, local databases, `.env`, real API keys
- generated TTS audio caches, benchmark outputs, or ad hoc test WAV files
- downloaded TTS models or model weights such as `.safetensors`, `.pt`, `.pth`, `.onnx`, `.gguf`
- installed optional TTS runtimes such as Irodori server checkouts, Docker volumes, or bundled model caches

Use:

```sh
python3 scripts/prepare_public_repository.py
python3 scripts/audit_distribution_release.py --project-root public/YuiVRMAIStudio_Public
```

Do not publish or package while that audit reports blockers.

## Cleanup Rule

Generated files may be deleted after confirming they are not the only copy of source or release artifacts. Source divergence must be merged first. The iOS fixes from `builds/unity_2022_3_62_patch_test/unity` are already merged, so that workspace can be archived or deleted after one final verification that no unmerged source-only files remain.
