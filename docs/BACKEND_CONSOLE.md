# Backend Console

Backendで使うAIと声を選び、アプリに接続するための管理画面です。アプリ単体のLocal/Direct APIでも会話できます。BackendではPCのエンジンや複数のAPI、記憶・履歴をまとめて扱えます。

Backendを通常のlauncherで起動し、そのPCのブラウザで http://127.0.0.1:8000/admin/ を開きます。ポートを変えた場合はURLも合わせてください。管理画面はこのPC専用です。

1. ホームの接続先をYuiアプリのBackend設定へ入力します。
2. 「AIと音声」で提供元・モデル・接続先を選び、保存します。ローカルエンジンは別途起動が必要です。
3. 「試す」で会話と声を確認します。外部APIの実行では入力が送信され、利用料金が発生する場合があります。
4. 「記憶」「履歴と利用状況」で利用者・キャラクターを選びます。端末内の記憶とは別です。

APIキーは値を再表示せず、設定有無を表示します。空欄の保存で既存キーは消えません。解除は「このキーを解除」で明示します。設定は既存.envを保ち、backend/data/admin-settings.jsonへ差分を保存します。このファイルにはキーを含めることがあるため、公開・共有しないでください。保存は次のリクエストから反映します。処理中の会話・Realtimeには開始時の設定が使われます。

別端末からは信頼できるVPNのアドレスとBackend待受を合わせて使います。管理UIはlocalhost限定です。アプリ用APIには認証がないので、インターネットに直接公開しないでください。日次利用値は目安で、料金や通信を自動停止しません。

新しい提供元はapp/core/capabilities.pyの能力定義とapp/providers/router.pyのadapter登録を追加します。共通設定schemaでGUIフォームを生成し、実行には既存APIを使います。提供元固有の調整はadapterと設定schemaで扱ってください。現行は単一Backendプロセスを前提とします。複数workerやreverse proxy経由の管理UIは対象外です。

RAG資料取込・embedding索引、端末とBackendの記憶同期は未実装です。

右上「実行状況」は、応答が遅い・失敗した・予想と違う提供元が使われた時に開きます。1回の処理ごとに、使用した提供元、待ち時間、確認できた失敗原因、次の確認先を表示します。「原因と対処を確認」から該当処理へ移動し、「関連設定を開く」で修正できます。原因不明のエラーは断定しません。

失敗・代替、応答待ちで絞り込めます。直近30分を基本に、この起動中の記録も選択できます。成功した処理は折りたたみ、技術情報には処理ID・HTTP状態・参照件数を表示します。件数や文字数はLLMの理解の正しさを証明しません。更新は一時停止できます。

本文・キー・ファイル内容・生のCLIログは収集しません。最大24時間の一時metadataで、再起動すると消えます。1000イベントの保持上限はメモリ保護のためで、表示件数の目標ではありません。保持上限で省略された場合は知らせます。ライブ音声の接続状態は動作テスト画面で確認します。


「読み上げ」では、保存した声と接続先を別に管理します。VOICEVOX/Aivisは話者・スタイルを自動取得、Irodoriは対応APIごとにモデルや声の指定を表示します。試聴した後に名前を付けて保存し、アプリのキャラクター設定から「Backendの保存した声を選ぶ」で割り当てます。割当はキャラクターとBackend接続先ごとに端末で保持します。別の接続先へ同じIDを勝手に流しません。従来の音声設定は自動変更しません。

声設定はbackend/data/voice-library.jsonへ保存します。接続先にキーを設定した場合、このファイルにもキーが含まれます。公開・共有・配布ZIPへ含めないでください。初期環境に含まれる音声、追加TTSの導入とライセンス、互換APIの手動設定は[音声導入ガイド](BACKEND_TTS_GUIDE.md)を参照してください。代替音声は選択した別プリセットを1回試します。試聴では代替せず、選んだ声の結果を確認します。
