# macOSへの不具合・検証引き継ぎ

更新日：2026-10-11。Windowsでの検証と、GitHub取得コードの共通経路調査に基づく。**この作業環境からMac実機を操作していない。** 以下の「確認」はWindows実機、共通Pythonコードのテスト、またはコード上の条件を指す。Mac実機での再現を済ませた意味ではない。[Windowsの全体記録](WINDOWS_VALIDATION_20261011.md)。

## 確認できた共通経路と修正

| 経路 | 原因・影響する条件 | 修正とMac側での確認 |
| --- | --- | --- |
| Irodoriの初期音声ライブラリ | `backend/app/core/irodori_presets.py` がMLX用の性別・言語パラメータをサーバー形式にも付与。サーバー形式の能力検査で422になり、合成へ到達しない。Windows GUIで再現。MacでもIrodori-TTS-Server形式を設定した場合に同じ経路 | 形式に応じて初期値を生成。サーバー形式は声IDと説明、MLX形式は従来の性別・言語を保持。両形式の3声を能力解決するテストを追加。Mac MLXの実合成と、Macでサーバー形式を選ぶケースを実機確認する |
| SoundStretch自動探索 | `backend/app/providers/http_tts.py` がUnix実行ファイルとWindows exeをOSに関係なく探索。混在時のWindows誤選択、Windows exeだけあるMacでの誤選択が起こりうる | 自動探索をOSに合った名前へ限定し、Unixでは実行権限も検査。Windows/Macの探索条件を模擬して回帰テスト。Macで実バイナリを使用した速度・高さ変更を確認する。明示設定したパスは利用者指定を維持 |
| LM Studio / LiteRTサーバーの返答 | `backend/app/providers/lmstudio_chat.py` が空のchoices・空本文を成功の定型文に変換し、本文がない応答では生のレスポンスJSONを表示しうる。thinkingだけ・tool_callsだけの応答も条件。共通コードで7条件の失敗を再現 | 本文が取得できない／正規化後に空なら `ChatProviderError` とし、ルートの既存502エラー処理へ渡す。生の応答JSONへの代替を除去。通常文・構造化出力・テキストブロックは維持。Mac実サーバーで会話・未ロード・thinkingだけの応答・接続停止を確認する |

保存済み音声ライブラリのあるMacでは、初期値修正だけで古いMLXパラメータが自動移行されるわけではない。既存声を保持したまま、MLX→サーバーへ接続先を変えた条件を確認する。GUIは接続先変更時に声・調整をリセットするが、設定ファイルの直接変更や旧データ移行の経路も確認する。任意の保存済み値を黙って削除する移行は今回実装していない。

## Windows STT修正とMacへの影響

Windows＋LiteRT-LM 0.17.0＋RTX 5070 Tiで短い発声が長い不正な認識へ崩れる問題を調査。GPUでの認識品質の不安定さは比較で確認したが、特定のGPUカーネル・ドライバー不具合までは特定していない。WindowsのSTTだけCPUへ固定し、会話GPUは維持した。**Mac/iOSをCPUへ固定する変更ではない。**

`scripts/yui_desktop_inference.py` の書き起こし専用system指示・決定的サンプラー・入力WAV検査・無音・過剰出力検査・日本語空白整理は共有変更。CPUだけでは発声した命令への回答が出るケースがあり、書き起こし専用指示も必要だった。Macでは「この文章をそのまま書いて」「計算して」などの発声が文字起こしされ、命令実行されないことを確認する。英語の単語間空白や句読点の確認も必要。

Unityのローカル音声入力上限は30秒へ変更。API経路の上限を一律30秒へ変更していない。実際の録音位置が0のときにバッファ全体を送る経路を拒否する。Mac/iOSでも録音開始直後、即停止、30秒境界、キャンセル、入力途中の提供元変更、API／Backendへの切り替えを確認する。ローカルモデルは長い音声の自動分割を行わない。

Windows上には一致するUnity 6.3 Editorがないため、C#の変更・Editorテスト・Mac/iOS再ビルドをここで成功扱いしない。STT実験結果は `tests/fixtures/windows_stt_validation_20261010.json` に記録。合成音声の限定的な試験であり、一般的な認識精度の保証ではない。

## 疑わしいがMac実機で未確認の条件

| 条件 | 調べる理由・次の試験 |
| --- | --- |
| 日本語・空白のファイル名、ファイルピッカーのキャンセル、二重クリック | Windows VRM0取り込み・切り替え・再起動復元は成功。MacのNSOpenPanel、iOSのファイルアクセス、VRM1、Avatar Bridge ZIPは別経路として確認する |
| アバター一覧の破損、元ファイル削除、インポート中の終了 | 保存とバックアップ・失敗復旧の実装はあるが、Mac実機で破損復元を通していない。既存キャラクターを保ったまま、隔離データで再現する |
| E4BとSTT/TTSの同時利用、モデル切り替え後のキャッシュ | Windows E4Bの実会話は成功。Mac/iOSはメモリ圧迫・再選択・中止・復帰を確認。会話モデル変更で標準E2BのSTTを失わないことも確認する |
| Irodori初回の追加ダウンロードと時間制限 | Windows初回合成で透かし処理用SilentCipherの取得とロードが発生。温まった試験だけでは完全オフライン初回の成功は保証できない。Macの実行方式でもコールド起動・ネットワーク断を個別に確認する |
| Python環境変数、実行ファイルの権限、サービス終了・再起動 | MacランチャーのPYTHONHOME/PYTHONPATH除去に既存テストあり。ただしWindowsのテスト実行ではPOSIXランチャーテストをスキップ。Mac上でそれらを実行する |
| 長いthinking、空本文、途中終了、遅い外部モデル | 外部接続は90秒・非ストリーミング。今回の空本文拒否だけで全モデル互換は保証できない。上限・失敗表示・履歴保存・再試行・同時要求を確認する |
| 外部API・ライブ音声・画像の実接続 | Windows環境にAPIキーなし。モックを通した機能と外部サービスの実動作を区別して確認する |

Windowsのファイル権限テストはPOSIXの0600検査を適用していない。これはWindows ACLを検証済みにする変更ではない。Macでは従来のPOSIX権限検査を継続する。

## 今後のモデル追加とCSV機能

[任意ローカルLLMの検討メモ](LOCAL_LLM_EXTENSION_NOTES.md)に、追加登録基盤、ファイル取り込み案、LM Studio／Ollama／llama-server／vLLM接続案、Backendとモバイルの役割、パラメータ数を固定しない評価方針、CSV作業モードへの意見をまとめた。**未確定の提案であり、実装前の検討が必要。**

Backend GUIの基本実装はGitHubに既にある（`backend/app/static/admin/`）。Macローカルだけに残っている未pushの改良の有無は、このWindows環境では確認できない。Mac側で `git status` と `git log` を確認し、ローカル差分を保全してから取り込む。
